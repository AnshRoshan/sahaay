# Friend interview — Phase 0

> Sahaay is built for one real person. Fill this in **before** finalising behaviour. Each answer maps to a concrete product decision.

**Friend / shop:** ______________  **Date:** ________  **Interviewer:** ________

| # | Question | Answer | Product decision it drives |
|---|---|---|---|
| 1 | What decision wastes the most time every week? | | Which recommendation type to polish first (reorder vs supplier vs slow-moving) |
| 2 | What do you usually check before making that decision? | | Evidence rows to show; evidence drawer order |
| 3 | What information do you wish you had? | | New signals / data columns to request |
| 4 | What decision have you regretted recently? | | Golden test case for evaluation (replay with his data) |
| 5 | What do you track in Excel / WhatsApp / POS? | | Import format, aliases, future integration order |
| 6 | What would you never allow software to do automatically? | | Permission list in Settings; keep human-approval gates |
| 7 | Would you trust an AI recommendation? | | How much evidence to show by default; abstention tone |
| 8 | What evidence would you need before acting? | | Evidence drawer defaults; "show raw data" prominence |
| 9 | How often would you want a briefing? | | Workflow schedule + channel (WhatsApp/voice/app) |
| 10 | What would make this genuinely useful after the hackathon? | | Roadmap order |

## Follow-ups to ask
- Who is your usual supplier per product? What do you do when they're out of stock?
- What are your real limits: max spend per order, max units, storage?
- Do you order on fixed days (sets the *review period*)?
- Do sizes/variants behave as one product or separately?
- Weekend/festival patterns you already know about?
- Language preference for briefings (English/Hindi/Gujarati…)?

## After the interview
1. Update `Rules & settings` with his limits.
2. Update `CONTEXT.md` → *Open questions*.
3. Replace the demo dataset's assumptions where he disagrees.
4. Tick the Phase 0 items in `docs/TASKS.md`.
